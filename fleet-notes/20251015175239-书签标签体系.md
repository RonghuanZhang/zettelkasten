结论：用“分面标签体系 + 轻层级”最稳。先定规则，再给每一面建立受控词表。面向 Java/Golang 的技术书签可用下列分面与示例。

# 设计原则

- 少而稳：核心分面 ≤8，每面首批 7–20 个词。
    
- 可组合：每条书签打 3–6 个标签，避免单标签或标签爆炸。
    
- 一致命名：全小写、`-` 连接、英文优先；中文作别名。单数，不用缩写除非业内通用。
    
- 版本与状态可选：只有确实影响筛选时才打。
    

# 推荐分面（Facets）

按顺序打标签：`域 → 技术栈 → 概念 → 活动 → 生命周期 → 来源/格式 → 重要度/状态`

- **f:domain**（领域）  
    `backend, api, distributed-systems, databases, caching, message-queue, devops, sre, security, testing, performance, data, ai, frontend`
    
- **f:stack**（语言/框架/平台）  
    `go, java, spring, spring-boot, grpc, protobuf, netty, jvm, kotlin, maven, gradle, docker, kubernetes, helm, istio, aws, gcp, redis, mysql, postgres, kafka, rabbitmq, etcd, consul, pulsar`
    
- **f:concept**（概念/模式）  
    `concurrency, goroutine, channel, memory-model, gc, locks, immutability, microservices, circuit-breaker, saga, idempotency, eventual-consistency, tracing, observability, oauth2, oidc, jwt`
    
- **f:activity**（你“做什么”）  
    `howto, checklist, reference, tutorial, deep-dive, postmortem, benchmark, cookbook`
    
- **f:lifecycle**（工程阶段）  
    `design, spike, prototype, implementation, review, testing, debugging, optimization, deploy, incident, retro`
    
- **f:source**（来源/格式）  
    `official-docs, rfc, blog, paper, talk, slides, repo, gist, playground, QnA`
    
- **f:priority**（重要度与时间性，可选 0–2 个）  
    `must-read, to-read, evergreen, outdated`
    
- **f:status**（你的处理状态，可选）  
    `saved, annotated, archived`
    

> 若工具不支持“分面”字段，就把前缀并入标签，如 `stack:go`, `concept:goroutine`。

# 分类与层级

- 一级用分面，二级只在必要时分层。例：  
    `domain:databases` → `databases/transaction`、`databases/indexes`  
    规则：层级不超过 2 级；同一分面的层级深度保持一致。
    

# 命名规范

- 全小写、`-` 连接：`spring-boot`、`eventual-consistency`。
    
- 版本：确有差异才标，如 `java-17`、`kafka-3.x`。
    
- 别名表：`go=golang`、`observability=o11y`（统一收敛到主标签）。
    

# 示例标注

1. 文章《Go 内存模型解读》  
    `domain:backend stack:go concept:memory-model activity:deep-dive source:blog priority:must-read`
    
2. GitHub：Spring Boot 3 官方迁移指南  
    `domain:backend stack:spring-boot concept:migration activity:checklist source:official-docs`
    
3. 视频《Kubernetes HPA 实战》  
    `domain:devops stack:kubernetes concept:auto-scaling activity:talk source:talk lifecycle:deploy`

# 工作流（低摩擦）

- 新书签：先打 `domain` 和 `stack`，再补 1–3 个 `concept`，最后按需加 `activity/source/priority`。
    
- 每周整理 10 分钟：合并同义词，删除 0 命中标签，移动越界标签到正确分面。
    
- 月度审计：导出列表，按标签计数找冗余和黑洞。
    

# 工具落地建议

- Raindrop/Pinboard/Omnivore：用标签前缀方案，支持批量替换与规则。
    
- Obsidian：把书签落为 Markdown，YAML front-matter 存标签，配 Dataview/Templater。
    
- 浏览器自动化：用书签脚本或 Raycast/Alfred 模板预填常用分面。
    

# 质量守则

- 不混分面：不要把 `kubernetes` 放进 `concept`。
    
- 不贴心情词：`cool`、`interesting` 一律禁用。
    
- 不超 10 标签/项。
    
- 首选主标签，不新造近义词，必要时加别名映射。
