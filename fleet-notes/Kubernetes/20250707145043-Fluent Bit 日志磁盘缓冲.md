默认情况下，上面 Collector 启动日志中提到的：

```
[ info] [storage] in-memory
```

意味着 **Fluent Bit 的存储层（storage layer）当前运行在 “in-memory” 模式**，也就是所有待重试或暂存的日志都会缓存在容器的内存中。如果 Pod 重启或容器崩溃，这些缓存在内存中的日志就会丢失。

---

## 一、内存缓冲 vs. 磁盘缓冲

| 模式             | 缓冲位置       | 持久化重启后保留 | 风险           |
| -------------- | ---------- | -------- | ------------ |
| **in-memory**  | 容器内存       | 否        | 容器重启/崩溃会丢失数据 |
| **filesystem** | 本地文件系统（文件） | 是        | 需额外磁盘空间      |

---

## 二、开启文件系统缓冲（推荐）

你可以在 Fluent Bit 的 `[SERVICE]` 段里增加 **存储相关配置**，让它把缓冲数据写到磁盘：

```ini
[SERVICE]
    Flush         1
    Daemon        Off
    Log_Level     info
    HTTP_Server   On
    HTTP_Listen   0.0.0.0
    HTTP_Port     2020

    # ────────── 开启磁盘存储 ──────────
    storage.path       /buffers       # 缓冲文件存放目录
    storage.sync       normal         # 同步模式：normal / full / always
    storage.checksum   on             # 记录校验和，防止损坏
    storage.backlog_limit 128         # 最多同时缓冲 128 chunks
```

### 步骤

1. **修改 Collector ConfigMap**（`log-collector-config`）的 `fluent-bit.conf`，添加上述 `storage.*` 设置。
2. **为缓冲目录准备持久卷**（PVC 或 hostPath），并挂载到容器的 `/buffers`：

   ```yaml
   volumeMounts:
     - name: buffer-store
       mountPath: /buffers
   volumes:
     - name: buffer-store
       hostPath:
         path: /var/lib/fluent-bit/buffers   # 或使用 PVC
   ```
3. **应用更新**，Rolling Update 会在磁盘上持久化缓冲数据，即使 Fluent Bit 重启也不会丢失未发送的日志。

---

## 三、示例片段

下面是你的 Collector StatefulSet 中，针对 Fluent Bit 容器的修改示例（ConfigMap 与 StatefulSet 节选）：

```yaml
# ConfigMap log-collector-config 中的 fluent-bit.conf
fluent-bit.conf: |
  [SERVICE]
      Flush         1
      Daemon        Off
      Log_Level     info
      HTTP_Server   On
      HTTP_Listen   0.0.0.0
      HTTP_Port     2020

      storage.path       /buffers
      storage.sync       normal
      storage.checksum   on
      storage.backlog_limit 128

  @INCLUDE input-forward.conf
  @INCLUDE filter-simplify.conf
  @INCLUDE output-files.conf
```

```yaml
# StatefulSet log-collector 的 volumeMounts / volumes
      - name: fluent-bit
        image: fluent/fluent-bit:1.5
        volumeMounts:
          - name: fluentd-config
            mountPath: /fluent-bit/etc/
          - name: logs
            mountPath: /logs
          - name: buffer-store
            mountPath: /buffers
      volumes:
        - name: fluentd-config
          configMap:
            name: log-collector-config
        - name: nginx-config
          configMap:
            name: log-nginx-config
        - name: buffer-store
          hostPath:                   # 或改为你的 PVC
            path: /var/lib/fluent-bit/buffers
```

---

### 四、小结

* **默认 in-memory 模式**：简单易用，但有丢失风险。
* **切换到 filesystem 模式**：需要配置 `storage.path` 并挂载持久卷，能够在重启后保留未发送日志，提升可靠性。

根据你的生产需求，建议 **开启文件系统缓冲** 并为 `/buffers` 目录预留合适的磁盘空间，以保证在网络短暂不可用、Collector 重启或负载高峰时都不丢日志。
