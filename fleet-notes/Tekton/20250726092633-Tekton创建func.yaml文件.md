你想在 `git-clone` 拉取代码后，在源码目录中（比如某个子目录）**添加一个新文件**，可以通过在后续 task 中添加一个 `script` 步骤来实现。

---

## ✅ 实现方式：

在 `fetch-sources` 任务之后，加一个新的 task，比如 `add-custom-file`，向指定路径添加文件。

下面是完整示例：

```yaml
    - name: add-custom-file
      runAfter:
        - fetch-sources
      taskSpec:
        workspaces:
        - name: source
        params:
        - name: filePath
          description: Relative path to file (inside the repo)
          type: string
        - name: content
          description: Content to write into file
          type: string
        steps:
        - name: write-file
          image: alpine
          script: |
            #!/bin/sh
            mkdir -p "$(dirname "$(workspaces.source.path)/$(params.filePath)")"
            echo "$(params.content)" > "$(workspaces.source.path)/$(params.filePath)"
      params:
      - name: filePath
        value: path/to/your/file.txt  # 例: src/generated/config.yaml
      - name: content
        value: |
          key: value
          foo: bar
      workspaces:
      - name: source
        workspace: source-workspace
```

---

## 🔍 说明

* `runAfter`: 确保 `git-clone` 完成后才运行此任务
* `filePath`: 你希望写入文件的相对路径，**以源码目录为根目录**
* `content`: 文件内容，支持多行
* `workspace.source`: 复用 `git-clone` 使用的 workspace，实现文件共享

---

## 🧠 示例用途

* 在 `./src/config/app-config.yaml` 中生成配置文件
* 写入构建元信息（如 commit hash、时间戳）
* 创建触发标志文件（如 `.ready`）

# 条件判断

是的，这是可以做到的，虽然 Tekton 本身的 `$(params.name)` 语法不会直接支持 **条件判断**，但你可以在 Task 的 shell 脚本中通过 `sh` 的方式实现你要的逻辑：**如果参数存在就输出 `name: xxx`，否则不输出任何东西。**

---

## ✅ 示例 Task：根据参数是否存在写入文件

```yaml
- name: conditional-write
  runAfter:
    - fetch-sources
  taskSpec:
    params:
    - name: name
      type: string
      default: ""  # 默认空字符串，表示未设置
    - name: filePath
      type: string
    workspaces:
    - name: source
    steps:
    - name: write-file
      image: alpine
      script: |
        #!/bin/sh
        FILE="$(workspaces.source.path)/$(params.filePath)"
        mkdir -p "$(dirname "$FILE")"

        # 只在 name 不为空时写入
        if [ -n "$(params.name)" ]; then
          echo "name: $(params.name)" >> "$FILE"
        fi
  params:
  - name: name
    value: $(params.name)  # 上游 Pipeline 中定义的参数
  - name: filePath
    value: path/to/output.yaml
  workspaces:
  - name: source
    workspace: source-workspace
```

---

## 🔍 说明

* `default: ""` 确保 `params.name` 不传也能执行，不会报错
* `if [ -n "$(params.name)" ]` 是标准 shell 写法，判断字符串是否非空
* `>> "$FILE"` 将内容追加写入文件中（你也可以用 `>` 覆盖写入）

---

## ✅ 最终行为如下：

| 传入参数 `params.name` | 输出内容（在文件中）          |
| ------------------ | ------------------- |
| `my-function`      | `name: my-function` |
| 空字符串或未传            | *文件无输出或空*           |

---

## ✅ 如果你需要多行文件，有条件地输出某几行：

你可以这样写：

```sh
#!/bin/sh
FILE="$(workspaces.source.path)/$(params.filePath)"
mkdir -p "$(dirname "$FILE")"
touch "$FILE"

echo "apiVersion: v1" >> "$FILE"
echo "kind: Config" >> "$FILE"

if [ -n "$(params.name)" ]; then
  echo "name: $(params.name)" >> "$FILE"
fi
```

* 只有在参数存在时才输出
* 文件输出格式灵活可控
