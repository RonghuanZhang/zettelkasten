结论先说：**可以**。在 DDD + COLA 里，Gateway 是领域层对外部世界（其他限界上下文/第三方）的抽象，**供领域对象与领域服务使用**；应用层也可以用，但要分清用意与边界。下面按你列的三个问题逐一说清，并配上业务语义示例。

---

# 1) 领域对象（聚合/实体）什么时候调用 Gateway？

满足“外部信息直接参与本聚合的领域规则或不变式”时，由聚合直接调用更自然：

* **不变式校验必需**
  例：订单下单必须满足“授信额度 ≥ 应付金额”“风险分 ≥ 阈值”。
  `Order.place()` 内部通过 `RiskGateway` 获取 `RiskAssessmentVO` 来做判断。

* **领域行为计算所需的外部参数**
  例：报价需要汇率/税率/阶梯价规则：`PricingPolicy` 调 `FxGateway` 拿 `ExchangeRate`（VO）计算价格。

* **状态流转是否允许取决于外部事实**
  例：履约前校验地址可达与最早 ETA：`Order.confirm()` 内调 `LogisticsGateway` 得到 `DeliveryCapability`（VO）。

> 关键：**返回的是领域 VO/规则集/聚合**，而不是展示用 DTO；接口通过依赖注入传入，聚合只依赖抽象。

---

# 2) 领域服务什么情况下调用 Gateway？

**可以**。当规则**不适合放在单个聚合内**，但仍是“纯领域决策”，由\*\*领域服务（Domain Service）\*\*承载，并通过 Gateway 获取领域所需信息：

* **跨聚合的纯领域规则**
  例：一个折扣策略需要同时看“客户等级聚合 + 商品类目聚合 + 营销规则集”。这些外部信息通过 `CustomerGateway`、`CatalogGateway`、`PromotionGateway` 注入到 `DiscountDomainService`，产出 `DiscountPlan`（VO），再由订单聚合应用。

* **策略/规则引擎型能力**（仍是领域语义）
  例：风控规则集、路由策略、费率矩阵等，由 `RiskRuleGateway`/`RoutingGateway` 提供 `RuleSet` 或 `Matrix`，领域服务据此选择策略或计算。

* **需要可测试、可替换的外部信息，但不归某个聚合所有**
  例：账务记账科目映射来自“科目配置上下文”，`AccountingDomainService` 调 `CoAConfigGateway` 取得 `AccountMapping`（VO）完成分录。

> 约束与建议
>
> * 领域服务应保持**无副作用/幂等**（尽量纯函数风格）；Gateway 只用于**读外部事实**或取规则（不做跨系统命令）。
> * 若出现“流程编排、重试、事务边界、并发控制”等**用例级**问题，就不应放在领域服务，交给**应用服务**。

---

# 3) 应用层什么情况下调用 Gateway？

应用层（Application Service）负责**用例编排**与**事务边界**。它可以调用 Gateway，但动机不同于领域层：

* **用例前置的数据准备/聚合输入装配**
  例：下单用例需要收集“用户默认地址、首选支付方式、实时库存快照”，应用层先调 `UserProfileGateway`、`InventoryGateway`，把结果转为领域 VO，调用 `Order` 的行为。

* **多 Gateway 的编排、降级与容错**
  例：汇率主源失败时切备源、并做超时/重试/熔断；这些是技术性与用例级策略，适合放在应用层而非领域层。

* **跨聚合/跨上下文的一致性与事务协调**
  例：创建订单 + 预占库存 + 发送领域事件，属于用例事务边界；应用层组织调用，领域层聚合/服务只做业务决策。

* **CQRS 读侧**
  面向页面/报表的查询（`*Qry -> *DTO`）走应用层（或 Adapter），**不要走领域层/Gateway**。

> 不要在应用层拿到外部 DTO 直接传进领域对象。应在应用层或 Gateway 中**转换为领域 VO**再喂给领域。

---

## 小结对照（放进团队规范就够用）

| 场景                | 是否调用 Gateway  | 由谁调用             | 返回什么                          |
| ----------------- | ------------- | ---------------- | ----------------------------- |
| 单聚合的不变式/行为需外部事实   | ✅             | **领域对象（聚合/实体）**  | 领域 VO/规则集/聚合                  |
| 跨聚合的纯领域规则、策略选择    | ✅             | **领域服务**         | 领域 VO/规则集/计算结果                |
| 用例编排、容错、事务边界、数据准备 | ✅             | **应用层**          | 先转为领域 VO 再入领域；或用于 CQRS 读侧 DTO |
| 页面展示/报表/导出        | ❌（不用 Gateway） | 应用层/Adapter 调读模型 | DTO（非领域对象）                    |

### 极简示例（各层各得其所）

```java
// Domain VO & Gateway
public record ExchangeRate(Currency from, Currency to, BigDecimal rate) {
    public Money convert(Money src) { /*...*/ }
}
public interface FxGateway { ExchangeRate getRate(Currency from, Currency to); }

// 领域对象直接用（单一外部事实参与行为）
public class Order {
    public Money quote(Money baseUSD, Currency userCcy, FxGateway fx) {
        return baseUSD.currency().equals(userCcy) ? baseUSD : fx.getRate(baseUSD.currency(), userCcy).convert(baseUSD);
    }
}

// 领域服务用（跨聚合纯领域规则）
public class DiscountDomainService {
    public DiscountPlan plan(UserId uid, Basket b, CustomerGateway cg, PromotionGateway pg) {
        var tier = cg.tierOf(uid);                 // VO
        var rule = pg.ruleSetFor(b);               // RuleSet
        return rule.compute(tier, b);              // 产出领域 VO
    }
}

// 应用层用（编排/容错/装配）
@Service
public class PlaceOrderAppService {
    public OrderId handle(PlaceOrderCmd cmd) {
        // 读侧查询省略…
        AddressVO addr = userProfileGw.defaultAddress(cmd.userId());
        InventorySnapshot inv = inventoryGw.snapshot(cmd.items());
        // 装配聚合 + 调用领域行为
        Order order = Order.create(cmd, addr, inv);
        // 事务边界内持久化、发事件…
        return order.getId();
    }
}
```
