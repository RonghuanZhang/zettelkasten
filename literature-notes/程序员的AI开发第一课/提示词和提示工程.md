## 提示词

$提示词 = 定义角色 + 描述背景 + 任务目标 + 输出格式$

### 为什么定义角色 ？描述背景信息？

基于大模型的本质是基于上下文推断下一段要输出的内容，所以如果不定义角色，不给他额外的信息，大模型的输出就是通用的

## 提示工程

### 零样本提示（Zero-Short Promoting）

大模型本来就拥有很多知识，所以可以直接借助大模型的知识和推理能力，例如：

```text
判断这句话的情绪是正面还是负面：我今天非常开心
```

零样本提示可以处理简单的任务，如果任务不通用，效果就会大打折扣了。
### 少样本提示（Few-Short Promoting）

给大模型一些例子，帮助其进行推理

```text
例子1：  
句子：我讨厌下雨。  
情绪：负面

例子2：  
句子：这个电影真的太棒了。  
情绪：正面

现在判断以下句子的情绪：
句子：我今天非常开心。  
情绪：
```

### 思维链提示 （Chain-of-Thought Promoting）

通过给出明确的、一步一步的推理过程，提升大模型对复杂任务的推理能力，提高准确性。

比如一个零样本提示：

```text
问题：一个火车以每小时80公里的速度行驶，从甲地到乙地需要3小时。请问甲乙之间的距离是多少公里？  
答案：240公里。
```

使用思维链工程提示：

```text
问题：一个火车以每小时80公里的速度行驶，从甲地到乙地需要3小时。请问甲乙之间的距离是多少公里？  
思考过程：火车的速度是每小时80公里，行驶了3小时，所以可以用速度乘以时间来计算距离。80 × 3 = 240公里。  
答案：240公里。
```

### ReAct 框架 

* Reasoning
* Action

对比 CoT，ReAct 多了 Action 这一步，可以在大模型推导中采取行动，比如搜索网页等。

大模型为了完成任务，需要做一系列的任务，这些任务流程包括：

* 思考（Thought），决定下一步的行动
* 行动（Action），完成具体的工作
* 观察（Observation），对行动的结果进行评估，决定是否要结束这个任务

LangChain 的提示词模板 Demo：

```text
Answer the following questions as best you can. You have access to the following tools:

{tools}

Use the following format:

Question: the input question you must answer
Thought: you should always think about what to do
Action: the action to take, should be one of [{tool_names}]
Action Input: the input to the action
Observation: the result of the action
... (this Thought/Action/Action Input/Observation can repeat N times)
Thought: I now know the final answer
Final Answer: the final answer to the original input question

Begin!

Question: {input}
Thought:{agent_scratchpad}
```

ReAct 适用场景：

- **开放领域问答**：需要外部信息支持的问答
- **Agent框架**：如LangChain、AutoGPT中，需要语言模型调用工具（浏览器、计算器、Python执行器）
- **多步计划和执行**：如旅游规划、财务分析、任务分解    
- **知识不足时的策略**：当模型不知道答案时，能主动“搜索”或“调用函数”查找
