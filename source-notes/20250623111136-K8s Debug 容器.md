Distroless 和最小化 JRE 镜像出于安全和体积优化的考虑，**默认都不会包含** JDK 自带的诊断工具（比如 `jstack`、`jmap`、`jstat` 等），因为它们并不属于运行时的“必需依赖”([github.com][1])。下面是几种常见做法来满足在容器内执行 `jstack` 的需求：

---

## 1. 使用带完整 JDK 的运行时镜像

最直接的方法是，你在 Runtime Stage 不用 JRE 镜像，而改用 **完整的 JDK** 镜像，比如：

```dockerfile
FROM eclipse-temurin:17-jdk-jammy
# …
COPY target/hive-application-start-*.jar /app/app.jar
ENTRYPOINT ["java","-jar","/app/app.jar"]
```

这样镜像里就自带了 `jstack`、`jmap` 等工具；缺点是镜像体积相对较大（通常几百 MB）。

---

## 2. 基于 Distroless Debug 版本

Google 的 Distroless 也提供了 “debug” 变体，内置了一个极简的 BusyBox shell，使你能 `kubectl exec` 进容器。但要注意：

* **`gcr.io/distroless/java:debug`** 带 shell，却依旧不一定包含所有 JVM 工具；
* 有社区 issue 建议将那些小型的 **JVM instrumentation binaries**（约 10 KiB/个）打包进去，但截至目前官方镜像并未一并发布([github.com][2], [stackoverflow.com][3])。

如果你选择这个方案，还需要在多阶段构建中 **手动把这些工具** 从一个完整 JDK 镜像里复制进来，比如：

```dockerfile
# 从完整 JDK 镜像里拷贝 jstack
FROM eclipse-temurin:17-jdk-jammy AS tools
RUN mkdir /tools && cp $(dirname $(which java))/../bin/jstack /tools/

FROM gcr.io/distroless/java17-debian12:debug
COPY --from=builder /app/app.jar /app/app.jar
COPY --from=tools  /tools/jstack   /usr/bin/jstack
ENTRYPOINT ["java","-jar","/app/app.jar"]
```

---

## 3. 临时调试容器（Ephemeral Debug Container）

如果生产环境镜像严禁包含诊断工具，也可以借助 Kubernetes 的 **Ephemeral Container** 功能，将一个带调试工具的短命容器挂载到正在运行的 Pod：

```bash
kubectl debug pod/hive-app-xxxxx \
  --image=eclipse-temurin:17-jdk-jammy \
  --target=hive-app \
  --command -- sleep infinity
kubectl exec -it pod/hive-app-xxxxx-debug -- jstack 1
```

这样主容器依旧保持轻量，你可以随时在调试容器里运行 `jstack`、`jmap` 等。

---

### 小结

* **最简单**：直接用完整 JDK 运行时镜像（自带所有诊断工具）。
* **最小化**：用 Distroless Debug + 手动拷贝工具，或用社区 debug 版镜像，但要自行验证所需工具是否包含。
* **最灵活**：在 GKE 上通过 Ephemeral Container 动态挂载调试环境，无需修改原镜像。

根据你的安全策略和运维要求，任选一种即可在容器内顺畅使用 `jstack` 及其他 JVM 诊断工具。
