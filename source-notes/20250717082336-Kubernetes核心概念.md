以下是**Kubernetes 核心概念**，按从基础到进阶、从资源对象到架构的结构化梳理，帮助你系统掌握：

---

### 🏗️ **1. 核心对象（Workload 相关）**

| **概念**          | **作用**                                |
| --------------- | ------------------------------------- |
| **Pod**         | 最小的部署单元，封装一个或多个容器，拥有共享网络和存储。          |
| **ReplicaSet**  | 确保指定数量的 Pod 副本在任何时刻运行。                |
| **Deployment**  | 管理 ReplicaSet，实现无中断滚动更新与回滚。           |
| **StatefulSet** | 管理有状态服务，提供固定身份、顺序部署、稳定存储。             |
| **DaemonSet**   | 在集群所有（或指定）节点上部署一个 Pod，常用于日志、监控 Agent。 |
| **Job**         | 一次性任务，确保指定数量的 Pod 成功结束。               |
| **CronJob**     | 定时任务，周期性执行 Job。                       |

---

### 🌐 **2. 服务与网络**

| **概念**                 | **作用**                                                                             |
| ---------------------- | ---------------------------------------------------------------------------------- |
| **Service**            | 为 Pod 提供稳定的访问入口和负载均衡。<br>类型包括 ClusterIP（集群内），NodePort（节点IP+端口），LoadBalancer（外部LB）。 |
| **Ingress**            | 七层（HTTP/HTTPS）流量入口，配合 Ingress Controller 使用，实现反向代理、路由、SSL 终结。                      |
| **Ingress Controller** | 监听并实现 Ingress 规则的控制器，如 Nginx Ingress Controller。                                   |
| **NetworkPolicy**      | 定义 Pod 之间或 Pod 与外部的网络访问规则，实现网络隔离。                                                  |

---

### 💾 **3. 存储**

| **概念**                          | **作用**                       |
| ------------------------------- | ---------------------------- |
| **Volume**                      | Pod 内部容器共享的存储卷，生命周期与 Pod 相同。 |
| **PersistentVolume (PV)**       | 集群中的持久化存储资源，独立于 Pod 生命周期。    |
| **PersistentVolumeClaim (PVC)** | Pod 对 PV 的申请与绑定。             |
| **StorageClass**                | 定义不同存储类型的配置与动态供给策略。          |

---

### 🔑 **4. 配置与密钥管理**

| **概念**        | **作用**                                |
| ------------- | ------------------------------------- |
| **ConfigMap** | 存储非敏感配置信息，注入到 Pod 环境变量或挂载为文件。         |
| **Secret**    | 存储敏感信息（密码、token、证书），Base64 编码后注入 Pod。 |

---

### 🛡️ **5. 访问控制与安全**

| **概念**                                         | **作用**                   |
| ---------------------------------------------- | ------------------------ |
| **Namespace**                                  | 集群资源的逻辑隔离单元。             |
| **ServiceAccount**                             | Pod 访问 API Server 的身份标识。 |
| **RBAC**                                       | 基于角色的访问控制，定义谁对哪些资源有什么权限。 |
| **PodSecurityPolicy / Pod Security Admission** | 定义 Pod 安全策略，如运行用户、特权模式等。 |

---

### ⚙️ **6. 控制器与 API 资源**

| **概念**                             | **作用**                                                                |
| ---------------------------------- | --------------------------------------------------------------------- |
| **Controller**                     | 持续对比实际状态与期望状态，自动调节资源，常见如 Deployment Controller、ReplicaSet Controller。 |
| **CustomResourceDefinition (CRD)** | 定义自定义资源类型，扩展 Kubernetes API。                                          |
| **Operator**                       | 使用 CRD + Controller 封装领域运维逻辑，实现自动化管理。                                 |

---

### 🧩 **7. 核心组件（架构层面）**

| **组件**                 | **作用**                                              |
| ---------------------- | --------------------------------------------------- |
| **API Server**         | 集群的唯一入口，提供 REST API 接口。                             |
| **etcd**               | 保存所有集群状态的分布式键值存储。                                   |
| **Scheduler**          | 根据调度策略为 Pod 分配运行节点。                                 |
| **Controller Manager** | 运行各类控制循环，如 Deployment Controller、Node Controller 等。 |
| **kubelet**            | 节点代理，管理 Pod 生命周期，与 API Server 通信。                   |
| **kube-proxy**         | 维护 Service 网络规则，提供负载均衡。                             |

---

### 📌 **8. 其他重要概念**

* **Label & Selector**
  资源打标签与选择器，核心于服务发现与调度。

* **Annotations**
  资源注解，存储非标识型元数据。

* **Taint & Toleration**
  节点污点与容忍，控制 Pod 调度规则。

* **Affinity & AntiAffinity**
  Pod 亲和性与反亲和性，定义 Pod 与 Pod 或节点的调度关系。

* **Horizontal Pod Autoscaler (HPA)**
  根据 CPU/MEM 等指标自动调整 Pod 副本数。

---

### 📝 **总结**

> **Kubernetes 的核心概念体系 = 资源对象（Pod/Deployment/Service/Volume） + 配置管理（ConfigMap/Secret） + 安全隔离（Namespace/RBAC/ServiceAccount） + 网络存储 + 控制循环（Controller/Operator） + 集群组件架构（API Server/Scheduler/etc）。**
