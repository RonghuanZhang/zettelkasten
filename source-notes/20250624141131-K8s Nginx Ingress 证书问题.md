# Cert Manager 解决非通配符域名证书问题

好的，下面是一个**完整示例**，展示如何在 **GKE 上部署 NGINX Ingress Controller + cert-manager + Let's Encrypt TLS 证书自动化 + 自定义 header 注入（如 X-Request-ID）**。

---

## ✅ 整体目标

我们将实现以下效果：

- 使用 **NGINX Ingress Controller**（非 GCE Ingress）
    
- 自动申请并续期 **Let's Encrypt TLS 证书**
    
- 在 ingress 中使用：
    
    ```yaml
    nginx.ingress.kubernetes.io/configuration-snippet: |
      more_set_input_headers "X-Request-ID: $request_id";
    ```
    

---

## 📦 第一步：安装 NGINX Ingress Controller

```bash
helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx
helm repo update

helm install nginx-ingress ingress-nginx/ingress-nginx \
  --namespace ingress-nginx --create-namespace \
  --set controller.publishService.enabled=true
```

---

## 🔐 第二步：安装 cert-manager + ClusterIssuer（使用 Let's Encrypt）

### 安装 cert-manager：

```bash
kubectl apply -f https://github.com/cert-manager/cert-manager/releases/latest/download/cert-manager.yaml
```

### 创建 ClusterIssuer：

```yaml
# cluster-issuer.yaml
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-prod
spec:
  acme:
    email: your-email@example.com
    server: https://acme-v02.api.letsencrypt.org/directory
    privateKeySecretRef:
      name: letsencrypt-prod-private-key
    solvers:
      - http01:
          ingress:
            class: nginx
```

```bash
kubectl apply -f cluster-issuer.yaml
```

---

## 🌐 第三步：创建 Ingress + Certificate + 注入请求头

```yaml
# ingress.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: my-ingress
  namespace: default
  annotations:
    kubernetes.io/ingress.class: "nginx"
    cert-manager.io/cluster-issuer: "letsencrypt-prod"
    nginx.ingress.kubernetes.io/configuration-snippet: |
      more_set_input_headers "X-Request-ID: $request_id";
spec:
  tls:
    - hosts:
        - your-domain.com
      secretName: my-tls-secret
  rules:
    - host: your-domain.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: your-service
                port:
                  number: 80
```

---

## 🔄 第四步：DNS 设置

将 `your-domain.com` 的 A 记录指向 NGINX Ingress 的外部 IP：

```bash
kubectl get svc -n ingress-nginx
```

找到：

```bash
nginx-ingress-controller LoadBalancer ... EXTERNAL-IP ...
```

用这个 EXTERNAL-IP 设置你的 DNS A 记录。

---

## 🧪 验证

1. 访问 [https://your-domain.com](https://your-domain.com/)
    
2. `curl -v https://your-domain.com` 应该看到带有 `X-Request-ID` 的 header
    
3. 查看证书是否为 Let's Encrypt 签发

# Cert Manager 解决通配符域名证书问题

很好，我们继续完成基于 **`dns01` 验证的通配符证书配置**，目标是让 NGINX Ingress 自动使用 Let's Encrypt 签发的 `*.staging.example.com` 证书。

---

## ✅ 你将拥有的完整流程：

1. cert-manager 通过 DNS-01 验证请求 Let's Encrypt 通配符证书
2. 证书保存为 Kubernetes Secret `staging-wildcard-tls`
3. NGINX Ingress 使用这个证书，启用 HTTPS
4. 证书自动续期，无需人工介入

## ✅ 第二步：创建 Cloudflare API Token Secret

```bash
kubectl create secret generic cloudflare-api-token-secret \
  --from-literal=api-token='your-api-token' \
  --namespace=default
```

## ✅ 第三步：ClusterIssuer 配置（使用 DNS-01）

```yaml
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-dns
spec:
  acme:
    email: your-email@example.com
    server: https://acme-v02.api.letsencrypt.org/directory
    privateKeySecretRef:
      name: letsencrypt-dns-key
    solvers:
      - dns01:
          cloudflare:
            email: your-email@example.com
            apiTokenSecretRef:
              name: cloudflare-api-token-secret
              key: api-token
```

---

## ✅ 第四步：Certificate 资源（通配符证书）

```yaml
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: staging-wildcard-cert
  namespace: default
spec:
  secretName: staging-wildcard-tls
  issuerRef:
    name: letsencrypt-dns
    kind: ClusterIssuer
  commonName: "*.staging.example.com"
  dnsNames:
    - "*.staging.example.com"
  duration: 2160h  # 90d
  renewBefore: 360h  # 15d
```

cert-manager 会自动处理 DNS TXT 验证，并生成证书，保存在 `staging-wildcard-tls` 这个 secret 中。

---

# 手动域名通配符，避免 DNS 供应商 Token

好的，下面是基于 **手动 DNS-01 验证** 的完整示例，针对 `*.staging.com` 通配符证书，供你参考：

---

# 1. 创建 ClusterIssuer （手动 DNS-01）

```yaml
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-manual
spec:
  acme:
    email: your-email@example.com            # 换成你的邮箱
    server: https://acme-v02.api.letsencrypt.org/directory
    privateKeySecretRef:
      name: letsencrypt-manual-key
    solvers:
      - dns01:
          manual: {}
```

---

# 2. 创建 Certificate 资源（通配符）

```yaml
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: wildcard-staging-com
  namespace: default
spec:
  secretName: wildcard-staging-com-tls
  issuerRef:
    name: letsencrypt-manual
    kind: ClusterIssuer
  commonName: "*.staging.com"
  dnsNames:
    - "*.staging.com"
  duration: 2160h  # 90天
  renewBefore: 360h  # 15天
```

---

# 3. 申请证书流程说明

1. 你应用上面两个资源后，cert-manager 会创建对应的 `Challenge` 资源。
2. 你用以下命令查看需要添加的 TXT 记录：

```bash
kubectl describe challenge -n default
```

3. 在 `Challenge` 资源描述中找到类似如下内容：

```
DNSName: _acme-challenge.staging.com
Key: <一串字符串>
```

4. 登录你的 DNS 控制台，手动添加 TXT 记录：

| 类型  | 名称                           | 内容            |
| --- | ---------------------------- | ------------- |
| TXT | \_acme-challenge.staging.com | `<Key 中的字符串>` |

5. 等待 DNS 解析生效（通常几分钟到几小时）。
6. cert-manager 会自动检测到 TXT 记录后完成验证，生成证书。
7. 证书会保存在 Secret `wildcard-staging-com-tls` 中，可用于 Ingress TLS。

---

# 4. Ingress 引用示例

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: example-ingress
  namespace: default
  annotations:
    kubernetes.io/ingress.class: "nginx"
spec:
  tls:
    - hosts:
        - app1.staging.com
      secretName: wildcard-staging-com-tls
  rules:
    - host: app1.staging.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: your-service
                port:
                  number: 80
```

---

# 注意事项

* **每次证书续期时**，你都需要重复手动添加新的 TXT 记录。
* 建议续期前提前关注证书状态，避免过期导致服务中断。
